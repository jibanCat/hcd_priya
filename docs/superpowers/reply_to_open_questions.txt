8. Open questions for the user
"Tightly coupled to CDDF statistics" — what is the intended coupling? PRIYA has no precedent for putting CDDF moments into the emulator's input vector. Options I see: (a) condition GP inputs on CDDF parameters (a few f(N) amplitude/slope numbers); (b) emit per-class P1D + a separate CDDF predictor and combine analytically downstream; (c) train a joint emulator whose output is (P1D_forest, P1D_LLS, P1D_subDLA, P1D_DLA, CDDF_bins). Which is the design?

Reply:
c is the design in my mind. CDDF can be separate from the P1D, as we used to have T0 emulator. So basically two separate emulators is fine, but it would be nice to check if jointly training CDDF/P1D can help improve accuracy.
