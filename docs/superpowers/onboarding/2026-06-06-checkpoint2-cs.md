## Errors / overclaims / things the doc gets wrong (be specific; cite file:line + numbers)

1. **OVERCLAIM of certainty on the ~0.6σ magnitude.** doc §0 TL;DR line 21 calls it "a coherent +0.6σ low-k A_p bias" and §0 line 34-36 makes it the relocated load-bearing risk. But the EMU A_p mean +0.53 has SE 0.33 over n=8 → **only ~1.6σ significant** (`/tmp/outlier.py`), with per-sim signs **4 positive / 4 negative** (median +0.42). spec §8 line 202 states this honestly ("SE 0.31 → ~1.7σ, a *possible* coherent residual") but the consolidated doc's TL;DR drops the hedge. The mechanism is real and reproduced; the *size* is an n=8 point estimate with a wide CI. Recommend the doc TL;DR carry "~0.6σ (n=8, ~1.6σ significance)".

2. **The n_s EMU baseline mean (−0.24σ) is an artifact of ONE outlier sim** (`/tmp/outlier.py`): the −2.63σ sim (ns0.813) drives it; dropping it gives **+0.10σ**, median +0.02σ. spec §8 line 203 labels n_s "edge-contaminated" but the consolidated doc reports −0.24/−0.19 as if a coherent n_s residual exists. There is no coherent n_s EMU bias — it is one outlier. (Does not affect the slope gate, which uses FULL−EMU.)

3. **The "n_s box-edge effect" attribution is weakly supported** (`/tmp/edge.py`). spec §8 line 194 / doc §0 footnote attribute the larger fold-0 n_s biases to "the known n_s box-edge effect." But all 8 fold-0 sims sit at low ns_u∈[0.013,0.117] and within that range there is **no correlation** between edge-proximity and |bias| (r=+0.00); the most-edge sim (ns_u=0.013) has the *smallest* n_s bias (+0.066), and the interior spot-check at ns_u=0.436 has a −1.33σ n_s FULL bias (not smaller). The edge story is plausible but not demonstrated by these data.

4. **Imprecise mechanism prose: "z-COHERENT (the high-k response is biased the same way at every z)"** (doc §3 line 150, §0 line 32). My direct probe of the *raw* per-z high-k signed error (`/tmp/zcoherence.py`) shows the sign **flips** across z (−0.009 at z<2.5, +0.004 at z~3, ~0 at z>4), overall signed mean ≈ 0 (−0.0007), only 52% of z-bins positive. The ×18.6 accumulation is nevertheless REAL — but it is coherent in the **C_inv-whitened, A_p-Jacobian-projected** direction, NOT in the raw spectrum. The doc should say "z-coherent in the A_p-projected direction" — the literal "biased the same way at every z" is false for the raw error and could mislead a retrain effort.

5. **No committed script for the §3 reconciliation** (×18.6, +0.033σ z=3, 1.26× covariance ruler, 3%-diagonal −0.60σ). The commit `23744a2` contains only the two scripts I reviewed; neither computes these. I reproduced ×18.6 / +0.033 independently, so they are correct — but a load-bearing headline with no reproducible artifact is a process gap. 6. **Minor, PART C truth-floor uses `P_obs_true`-adjacent `d["P_filt"]` over a fixed z-window (2.2–4.6) pooled across ALL sims** (`diag_emu_lowk...py:73-81`). The floor is an *ensemble* SVD over rows; the emu error is *per-sim*. Comparing a per-sim error RMS to an ensemble-floor RMS is defensible as an order-of-magnitude "can the rank represent it" test, but it is not a per-sim floor — so "6–18×" is a pooled statement, not a guarantee each sim is 6–18× above its own floor. Acceptable for the qualitative verdict; worth a one-line caveat.

## My lens's take on the fork: correlated-in-k/z C_emu vs targeted emulator retrain (which, why)

**Strongly favor the correlated-in-k/z C_emu (path a), on pure implementability/risk grounds.**

- The likelihood **already dense-Choleskys a full (N,N) C_total** (`data_likelihood.py:436` → `gaussian_loglik`, lines 441-443 `jnp.linalg.cholesky` + `cho_solve`). C_emu currently enters as `jnp.diag(emu_var_flat)` at `data_likelihood.py:377`. Building a correlated C_emu means **replacing that one `jnp.diag(...)` with a dense flat (N,N) emu block** — the solve, the per-leg loop, the autodiff path, and `gaussian_loglik` are all unchanged. The cross-class 4×4 machinery (`rho_zb`, commit `3b5b20f`) already threads a non-diagonal per-k structure through `_emu_var_on_cache`; extending it to off-diagonal in (k,z) is an additive, contained change to one function. **Zero downstream certs invalidated.**
- A **retrain (path b) is the high-blast-radius option**: it mutates the trained `p_filt_basis` leaf + every Linear weight, which **invalidates the golden reference** (`tests/golden/legb_lf_golden.npz` would have to be regenerated — `scripts/make_legb_golden.py`), **re-opens all 8 LOSO folds**, and forces re-running every bias cert (the 0.067σ Fisher, the grad gate, this whole investigation). The payoff is uncertain: the floor argument shows the high-k coherent error is *reducible in principle* (above the rank-24 floor), but not that a retrain will hit a coherent-bias target rather than just lowering RMS. And per finding #1 the target itself is a ~1.6σ n=8 estimate — you would be retraining against a noisy objective.
- From a correctness standpoint the C_emu path is also the *honest* one: it marginalizes (inflates the error budget for) a mode we have characterized but not eliminated, rather than claiming to have fixed the emulator. Do (a) now; hold (b) as a later optional improvement once NUTS coverage says whether the mode actually bites.

**One caveat on path (a):** the C_emu must be built in a space consistent with how the bias enters. The mode is high-k-sourced but routed to low-k/A_p via the basis (PART B/D, r=−0.61). A correlated C_emu that is itself derived from the same `sigma_zb`/`rho_zb` cross-class vector must capture the **k-off-diagonal** low↔high correlation, or it will whiten the high-k variance without whitening the low-k *projection* of it. Co-design + re-measure the A_p/n_s bias WITH it before the cert (spec §7 line 173 already says this).

## Additional risks or missing checks

- **NUTS ≠ Fisher.** Everything here is a Fisher/Laplace MAP-shift projection. The σ(A_p)=0.43 posterior is ~40% wide and the n_s box edge is clearly active (one −2.7σ sim) → the true posterior may be non-Gaussian where the Fisher bias is least trustworthy. The coverage run is the arbiter (doc §5 flags this).
- **All 8 fold-0 sims live at low ns_u (0.01–0.12).** The fold-0 EMU/FULL means are an edge-of-prior sample, not a representative interior sample. The interior spot-checks (folds 3–5) are emulator-IN-SAMPLE so the emu-error component is understated there (correctly flagged). There is **no held-out interior-n_s measurement** of the EMU bias — the +0.6σ is characterized only at the n_s box edge. Recommend at least one held-out interior fold before trusting the magnitude.
- **MF re-measurement (Q2) is correctly flagged but unquantified.** The structural argument (LF-vs-LF, MF in neither side) is sound, but "MF acts on the same high-k channel → re-measure" means the +0.6σ number does not survive MF wiring. The cert is genuinely LF-only.
- **Floor is pooled, not per-sim** (finding #6) — the 6–18× is an ensemble statement.
- The reconciliation's covariance-ruler sub-claims (1.26×, 3%-diagonal −0.60σ) are unverified by me (no artifact).
